# skills/ — client-specific skills

The skills and specialists built **for this client** live here. They compose the agency-wide shared skills (`cosi-skills`) with this capsule's brand + knowledge to produce on-brand work.

**The test for what belongs here (dotKnowledge SPEC.md §3):** does this capability make sense independent of which subject's capsule is mounted, or does it only exist because of something particular to *this* client? Generic operating mechanism (a daily-briefing routine, a session-wrap-up ritual — anything that works the same way regardless of whose capsule is mounted) is console tooling, and never belongs here. A capability that only exists *because of* this client's own facts — a brand-voice checker built from their actual voice rules, a format-specific generator tied to their real deliverables — belongs here, because it's part of what makes this capsule a complete, portable artifact: if this client's relationship with CoSi ever ends, the skill should travel with the capsule, the same way their real brand guidelines would.

> Template — empty. Real client skills are added when the capsule is stamped. Keep them client-specific; anything reusable across clients belongs in `cosi-skills`, not here.

Pattern: `Shared role/skill (cosi-skills) + this capsule's brand + knowledge = on-brand work for <Client>.`
